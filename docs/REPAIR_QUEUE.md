# Repair countdown
For each part, review by stable shot number or actor name. Report remaining / total, passed, failed, pending. A repair round is not a new part or a reset. Only failed entries may be edited; pending entries need evidence first. Keep passing evidence unless directly invalidated by a changed dependency. Reopen only the affected shot/actor, record the actual failure and changed method, and check it against fresh evidence. If the count does not decrease, change method or report a concrete blocker; never fabricate zero. Camera review stores each shot's complete sample fingerprint and retains valid answers for untouched shots. Motion review records each actor and its measured drift/jump times. If evidence is invalidated, the count can rise truthfully. Keep original approval and render gates. The persisted history is in progress/<story>_<part>_repair_queue.json. Preview and CLI report these counts.
